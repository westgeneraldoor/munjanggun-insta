# 고객질문 기반 캐러셀 워크플로우

문장군 인스타 캐러셀은 생활 문제은행뿐 아니라 실제 고객 질문을 공식 소재 원천으로 사용한다.

## 역할 분담

| 역할 | 책임 |
|---|---|
| 상담 직원 | 고객이 실제로 물어본 질문을 원문에 가깝게 전달한다. 답변까지 정리할 필요는 없다. |
| Codex 총괄 | 질문을 분류하고 고객 불안, 콘텐츠 각도, 확인 질문, 제작 가능성을 정리한다. |
| 대표님 | 공식 답변, 조건, 예외, 금지 표현을 승인한다. |

## 질문 상태

```text
raw -> triage_review -> answer_review -> ready -> used
                    \-> merged
                    \-> hold
                    \-> rejected
```

| 상태 | 의미 | MD 제작 |
|---|---|---|
| raw | 상담 직원에게 받은 원문 질문 | 불가 |
| triage_review | 질문을 독립 소재로 둘지, 합칠지, 나눌지, 보류/폐기할지 판단해야 함 | 불가 |
| answer_review | 공식 답변, 조건, 예외를 대표님과 협의해야 함 | 불가 |
| ready | 콘텐츠 각도와 공식 답변이 확정됨 | 가능 |
| used | 이미 캐러셀 원고로 제작됨 | 불가 |
| merged | 다른 질문 또는 묶음 소재에 병합됨 | 불가 |
| hold | 조건이 복잡하거나 자료 부족 | 불가 |
| rejected | 브랜드/현실/상담 전환과 맞지 않음 | 불가 |

## 질문 정리 게이트

상담 질문은 원문 그대로 공식 소재은행에 쌓지 않는다.  
먼저 `triage_review` 상태에서 아래 결정을 내린다.

| 결정 | 의미 | 다음 상태 |
|---|---|---|
| keep_candidate | 독립 소재로 유지할 가치가 있음 | answer_review |
| merge_candidate | 비슷한 질문과 묶어서 하나의 소재로 다룸 | merged 또는 answer_review |
| split_candidate | 한 질문 안에 서로 다른 소재가 섞여 있음 | 새 질문으로 분리 |
| hold_candidate | 정책/가격/법무/운영 기준이 불명확함 | hold |
| reject_candidate | 인스타 소재 가치가 낮거나 브랜드에 맞지 않음 | rejected |

정리 기준:

- 같은 고객 불안이면 병합한다.
- 답변 기준이 완전히 다르면 분리한다.
- 상담 답변으로는 필요하지만 인스타 소재 가치가 낮으면 보류 또는 폐기한다.
- 가격, 결제, 세무, 타사 자재처럼 정책 리스크가 있는 질문은 공식 기준 전까지 보류한다.
- 질문이 많아도 `ready`로 바로 올리지 않는다.

## 직원에게 요청할 최소 형식

직원은 바쁘기 때문에 완성된 자료를 요구하지 않는다.

```text
고객이 자주 물어보는 질문을 생각나는 대로 적어주세요.
정확한 답변까지 안 적어도 됩니다.
고객이 실제로 말한 표현이면 더 좋습니다.
```

가능하면 아래 정보만 추가로 받는다.

```text
고객 질문:
실제 표현:
관련 제품: 중문 / 방문 / ABS도어 / 몰딩 / 기타
특이 조건:
```

빈도는 없어도 된다. 우선순위는 총괄이 아래 기준으로 판단한다.

- 구매 직전 불안을 해결하는가
- 상담/실측으로 자연스럽게 이어지는가
- 조건부 설명이 필요한가
- 많은 사람이 오해할 만한가
- 문장군 전문성이 드러나는가
- 저장형 체크리스트로 만들 수 있는가

## 대표님 협의 형식

고객질문 기반 소재는 바로 MD로 만들지 않는다. 먼저 아래 형식으로 대표님에게 가져간다.

```text
주제 후보:
고객 질문:
내가 본 고객 불안:
캐러셀 훅:
문장군 답변에서 확인 필요한 것:
조건/예외:
금지해야 할 표현:
제작 가치:
```

총괄이 먼저 질문을 정리해 `triage_review`에서 통과시킨 뒤, 대표님에게 공식 답변 협의를 요청한다.  
대표님이 공식 답변과 조건을 알려주면 해당 질문의 `data/questions/items/Q###.json` 상태를 `ready`로 올린다.  
`data/questions/CUSTOMER_QUESTION_BANK.json`은 전체 질문의 목차와 상태 인덱스 역할만 한다.

## 캐러셀화 원칙

고객 질문을 그대로 제목으로 쓰면 FAQ가 된다. 인스타 캐러셀은 질문 뒤의 불안과 오해를 훅으로 번역한다.

고객 질문 기반 원고는 아래 세 단계를 통과해야 한다.

1. 소재분석가: 질문 뒤의 고객 불안이 실제 구매 전 망설임인지 확인한다.
2. 브랜드팩트감사자: 대표님 공식 답변의 조건, 예외, 금지 표현이 원고에 반영됐는지 확인한다.
3. 인스타작가: 답변을 FAQ가 아니라 생활 문제, 오해, 실수 방지 프레임으로 바꾼다.

`ready` 상태는 원고 작성 가능 상태일 뿐 자동 승인 상태가 아니다.  
작성 후에는 `editorial_review`에 고객 문제, 단일 메시지, 문장군 이득, 전환 이유, 반려 리스크를 남긴다.

예시:

| 고객 질문 | 캐러셀 훅 |
|---|---|
| 중문은 언제 진행해야 하나요? | 중문, 이사 다 끝나고 하면 늦을까요? |
| 하루면 시공될까요? | 중문 설치, 하루면 끝날까요? |
| 철거 + 폐기물은 포함되어 있나요? | 철거·폐기물, 문장군도 별도로 안내합니다 |
| 댐퍼가 뭔가요? | 3연동 댐퍼가 뻑뻑하면 고장일까요? |

## 금지 사항

- 공식 답변이 없는 질문을 MD로 만들지 않는다.
- AS 기간, 설치 시간, 제작 기간, 가격, 포함 범위는 대표님 확인 전 숫자로 쓰지 않는다.
- 모든 현장에 같은 답을 적용하는 것처럼 단정하지 않는다.
- 제품 기능을 안전 보장, 방음 보장, 비용 절감 보장처럼 과장하지 않는다.
- 고객 질문을 FAQ처럼 딱딱하게 복붙하지 않는다.

## 운영 데이터

- 질문 목차: `data/questions/CUSTOMER_QUESTION_BANK.json`
- 질문 상세: `data/questions/items/Q###.json`
- 상태 리포트: `npm run status`
- 제작 후 연결: 캐러셀 MD의 `customer_question_ref`에 질문 ID를 기록할 수 있다.

## 파일 관리 원칙

- 상담 질문은 계속 늘어나므로 단일 JSON에 모든 답변을 누적하지 않는다.
- 신규 질문은 `data/questions/items/Q###.json`에 1질문 1파일로 저장한다.
- 목차 파일 `CUSTOMER_QUESTION_BANK.json`은 사람이 전체 상태를 빠르게 보기 위한 인덱스다.
- `triage_review` 상태 질문은 원문, 고객 불안, 정리 추천, 병합 후보만 가볍게 저장한다.
- `answer_review` 상태 질문은 정리 심사를 통과한 뒤 대표님 공식 답변을 기다리는 질문만 둔다.
- `ready` 상태로 승격할 때만 공식 답변, 조건, 금지 표현, 파생 캐러셀 후보를 상세히 기록한다.
- 한글 데이터는 PowerShell 인라인 스크립트로 직접 쓰지 않는다. 한글은 패치 또는 UTF-8 파일 기반 도구로만 수정한다.
