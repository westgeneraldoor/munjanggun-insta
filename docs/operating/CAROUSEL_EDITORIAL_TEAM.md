# 캐러셀 제작 총괄팀 운영 모델

문장군 인스타 캐러셀은 FAQ 답변지가 아니라, 실제 고객 불안을 인스타에서 멈춰 보게 만드는 MD 원고다.  
따라서 신규 원고는 한 명의 작성 결과가 아니라 아래 역할을 통과한 최종 산출물로 본다.

## 팀 구성

| 역할 | 책임 | 반려 권한 |
|---|---|---|
| 총괄 PD | 소재 선택, 최종 메시지, 브랜드 이득, 최종 승인 | 모든 단계에서 반려 가능 |
| 소재 분석가 | 고객 질문 뒤의 실제 불안, 구매 전 망설임, 상담 전환 가능성 분석 | 고객 문제가 약하면 반려 |
| 브랜드 팩트 감사자 | 문장군 기준, 제품/시공/비용/기간/AS 사실 확인 | 사실이 애매하면 반려 |
| 인스타 작가 | 첫 장 훅, 말맛, 슬라이드 흐름, 저장/공유 가치 설계 | FAQ처럼 읽히면 반려 |
| 전환 설계자 | 댓글 키워드, 무료 방문실측 견적상담 연결 이유, CTA 단일화 점검 | CTA가 억지면 반려 |
| 중복 감시자 | 기존 원고, 최근 10개 클러스터, 제목/각도 유사도 점검 | 의미 중복이면 반려 |
| QA 감시자 | JSON 구조, caption_card, 해시태그, 위험 표현, 검증 명령 확인 | 검증 실패 시 반려 |

## 승인 전 5문장 게이트

051번 이후 모든 신규 캐러셀 MD에는 `editorial_review`를 기록한다.

```json
"editorial_review": {
  "customer_problem": "고객이 실제로 불안해하는 문제를 한 문장으로 쓴다.",
  "single_message": "이 캐러셀이 끝까지 말하려는 단 하나의 메시지를 쓴다.",
  "brand_benefit": "이 글이 문장군을 더 믿게 만드는 이유를 쓴다.",
  "conversion_reason": "왜 댓글/DM/무료 방문실측 견적상담으로 자연스럽게 이어지는지 쓴다.",
  "rejection_risks": ["통과 전 확인한 반려 위험을 쓴다."]
}
```

고객 질문을 2개 이상 묶는 경우에는 아래 필드를 추가한다.

```json
"merged_question_rationale": "두 질문을 왜 하나의 캐러셀로 묶어도 메시지가 흐려지지 않는지 쓴다."
```

## 강제 반려 기준

아래 중 하나라도 해당하면 MD 제작 또는 승인 금지다.

- 첫 장이 고객의 생활 문제보다 제품 기능 설명으로 시작한다.
- 캐러셀을 읽고 남는 메시지가 두 개 이상이다.
- 고객에게 도움은 되지만 문장군에 남는 신뢰/상담 전환 이유가 약하다.
- 브랜드 기준이 불리하게 오해될 수 있는데 정직한 재프레이밍이 없다.
- 실제 문장군 기준과 다르게 포함/별도/기간/AS/서비스 가능 여부를 흐리게 쓴다.
- 기존 원고와 같은 불안, 같은 해결, 같은 CTA로 반복된다.
- 고객 질문 원문을 그대로 FAQ처럼 풀어쓴다.
- CTA가 댓글 키워드에서 끝나고 무료 방문실측 견적상담으로 이어지지 않는다.

## 고객질문 원고 특수 규칙

고객질문 기반 캐러셀은 `정확한 답변`만으로는 부족하다.

통과하려면 아래 세 가지가 모두 있어야 한다.

1. 고객이 왜 지금 이 질문을 하는지 보인다.
2. 문장군이 왜 이 질문에 답할 자격이 있는지 보인다.
3. 고객이 댓글이나 무료 방문실측 견적상담을 남길 이유가 보인다.

## 총괄 책임 원칙

팀원은 발견과 반려 의견을 낸다.  
최종 통과 책임은 총괄 PD에게 있다. 구조 검증 통과는 콘텐츠 승인과 다르다.
